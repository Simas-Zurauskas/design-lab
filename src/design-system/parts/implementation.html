07 Build

Tokens in one file, used by name.

Every value lives in src/theme.css. Screens and components use its names as Tailwind utilities (bg-primary, text-ink, rounded-card, font-display) — never a hex, never a palette class.

How theme.css grows

Start flat (one block of roles, as now). When the system needs more, split it top to bottom into tiers:

TierNamesWhat it holds
Primitives--<prefix>-<name>Raw values (every theme's colours). No utilities; no component reads them.
Contract--color-<role>The roles a theme sets — a new theme is one block of these.
Derived--color-<role>Computed from the contract (color-mix): muted, pressed, washes.
Component--<prefix>-<part>-*Per-part colours and sizes, when a part needs its own.

Plus the non-colour scales — type, spacing, radius, shadow, motion — as Tailwind namespaces where they make utilities. Never reset Tailwind's defaults in theme.css: the wireframes and Explorations use them.

Where things are

  • src/theme.css — every token; a re-skin edits only this file.
  • src/design-system/parts/*.html — this document, one part per section; design-system/system.css — its styles (.ds-*).
  • src/components/hifi/ — the parts; their shared CSS in components/hifi/css/ under one class prefix.
  • src/hifi/ — screens built from those parts.

Changing the system

  • A value: edit theme.css; check the pairs in Colour still pass.
  • A geometry number (Layout): change it here, in theme.css, and in the wireframe kit in the same edit.
  • A new part: its file in components/hifi/, its states on the Components canvas, its row in Components above.
